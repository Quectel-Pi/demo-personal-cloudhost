# 个人云主机用户指南

本指南适用于运行 Debian 13 的 Quectel Pi M2 局域网版本。

> 默认服务使用明文 HTTP，仅面向可信局域网。请勿直接暴露到互联网或转发服务端口。

## 1. 安装前准备

- 开发板已联网，并可以访问软件包仓库。
- 准备具有 `sudo` 权限的用户账号。
- 使用门户的手机或电脑与开发板连接在同一局域网。
- 如需 SSH，先配置并验证公钥。仅当服务用户存在已授权公钥时，安装程序才会关闭 SSH 密码认证。

## 2. 安装并打开门户

在开发板上克隆仓库：

```bash
git clone https://github.com/Quectel-Pi/demo-personal-cloudhost.git
cd demo-personal-cloudhost
sudo ./install.sh
```

按提示设置门户初始密码。安装程序会安装并启动所需服务。通过 `./install.sh --help` 查看可选参数；例如 `--no-ttyd` 可跳过浏览器终端，`--no-ssh-harden` 可保持 SSH 配置不变。

查看开发板的局域网地址：

```bash
hostname -I
```

在同一局域网的浏览器中打开 `http://<开发板IP>/`。PAM 系统账号认证可用时，使用配置的服务运行账号和对应系统密码登录；若安装程序使用密码哈希后备认证，则使用 `admin` 账号和安装时提供的密码登录。

## 3. 使用门户

- **概览：**查看系统资源和网络信息。
- **文件：**浏览配置的文件根目录、上传/下载文件及管理目录。默认文件根目录为服务用户的 home 目录。
- **站点：**将静态文件放入 `~/cloud/www`，然后访问 `/site/`。
- **终端：**如果安装了浏览器终端，可使用开发板上的本地 shell；它不是 SSH 客户端。
- **SSH：**使用门户显示的命令，从电脑终端连接开发板。需确保 SSH 已配置且在局域网内可达。

请妥善保管私钥和密码，不要将凭据放入共享目录或公开站点，也不要把机密文件放入静态站点目录。

## 4. SSH 访问

如客户端电脑尚无密钥，可生成一对密钥：

```bash
ssh-keygen -t ed25519
```

使用可信的常规配置方式，将公钥安装到开发板的服务用户账号下，然后在局域网内验证连接：

```bash
ssh -i ~/.ssh/id_ed25519 <用户>@<开发板IP>
```

接受主机密钥前，请通过可信渠道核对指纹。如果安装程序未找到已授权公钥，会跳过 SSH 密码登录加固，避免用户被锁在系统之外。

## 5. 维护

安装程序支持查看帮助和卸载：

```bash
sudo ./install.sh --help
sudo ./install.sh --uninstall
```

卸载会移除已安装的应用和服务，但保留 `~/cloud` 下的用户数据。系统维护或更换存储前，请另行备份重要文件。

可使用标准 systemd 命令检查服务和日志，例如：

```bash
systemctl status caddy cloudhost-portal
journalctl -u cloudhost-portal
```

## 6. 故障排查

| 现象 | 检查方法 |
|---|---|
| 门户无法打开 | 确认客户端与开发板位于同一局域网；用 `hostname -I` 查看开发板 IP；检查 `caddy` 和 `cloudhost-portal` 是否运行。 |
| 登录失败 | 确认当前使用的是 PAM 系统账号认证还是密码哈希后备认证，并使用对应账号和密码。 |
| SSH 拒绝连接 | 检查 SSH 服务状态、开发板网络连通性，以及用户名、密钥、地址和端口是否正确。 |
| 找不到浏览器终端 | 安装时可能使用了 `--no-ttyd`；需要该功能时请重新安装并启用终端。 |
| 文件不在预期位置 | 默认文件根目录是服务用户的 home 目录；静态站点目录是 `~/cloud/www`。 |

请勿通过将开发板或内部服务暴露到公网来解决访问问题。
